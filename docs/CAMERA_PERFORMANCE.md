# CYD 相机刷新率测量与优化

日期：2026-11-10。设备为 ESP32-2432S028R CYD、240 MHz、4 MB Flash、无 PSRAM，ESP-IDF 5.5.3 / LVGL 9.5.0；X2D 通过局域网 TLS/6000 提供 1920×1080 JPEG，屏幕显示区为 240×135。云 MQTT 与相机同时运行。

## 原来的四秒半从哪里来

之前记录的约 4.43 秒是实测成功更新间隔的中位数，不是固定帧周期，也不是硬件上限。旧代码在每张成功后额外等待 **2000ms**，下一张重新建立 TLS、登录、建立文件会话，再取图、解码和显示。2000ms 是早期为内存／网络共存保留的保守节流值，当时没有压测上限。

本轮先在电脑侧连续读取同一预览接口：每张重连的 12 张样本中位间隔约 **921ms**；复用会话的 12 张约 **231ms**，12 张 JPEG 内容均不同。电脑结果不包含板上解码／显示，不能直接当作 CYD 帧率，但说明取图接口可以快于四秒半。

## 板上对照结果

刷新间隔从前后两次**成功完成校验与显示**的日志时间计算；每轮排除前两张预热，切页产生的停取图空档单独剔除。范围是样本中的最小／最大值，不是硬件保证。

| 策略 | 成功图片数 | 稳态间隔中位数 | 稳态间隔范围 | 稳态取图／解码失败 |
| --- | ---: | ---: | --- | ---: |
| 每张重连，成功后等 2000ms | 12 | 4.105s | 3.994–4.320s | 0 |
| 每张重连，不额外等待 | 12 | 2.107s | 1.940–2.487s | 0 |
| 复用 TLS／文件会话，不额外等待 | 30 | 0.929s | 0.799–1.013s | 0 |
| 复用会话并合并控制包写入，实验项 | 40 | 0.920s | 0.788–15.056s | 1 |
| **采用：复用会话，成功后等 100ms** | **100** | **1.012s** | **0.897–1.157s** | **0** |

采用设置相对本轮旧策略约快 **4.06 倍**，接近每秒一张。0ms 测试给出了当前实现约每秒 1.08 张的样本中位数；采用设置保留 100ms 调度／请求间隔余量，不再固定空等两秒。100ms 是配置项，不表示取图本身只需 100ms。

100 张均通过完整性校验且 JPEG 内容有变化；这说明没有把同一字节序列反复当作新图片，不能由此推算摄像头的原始视频帧率。期间用户右滑回首页、左滑回监控页，确认恢复、颜色方向和触摸正常；有一次与切页对应的主动取图取消，不计为网络失败。统计中保留原始取消记录，没有把它当作丢失的成功图片。

所有对照轮次在云连接成功后均为 0 次云断开，未见崩溃／看门狗。各轮启动连接建立前均出现过一次断开／重试记录，未当作已经连接后的掉线。采用设置中，取图结束后的空闲堆最低为 68,228 字节，最大连续空闲块最低为 57,344 字节，任务栈剩余最低为 3,512 字节；这些不是 TLS 握手期间的全程内存最低值。

合并控制包写入没有带来明显收益，且该轮出现一次等待超时／重连，未纳入正式实现。单轮样本不能证明失败必然由合包造成，这里只记录实验现象。

各轮按顺序测试，JPEG 内容随真实打印变化，大小约 70–90KB，网络环境也可能变化。结果不是固定同一图片的纯 CPU 跑分，不承诺其他打印机、固件或弱网环境达到相同速度，也不是长时间稳定性保证。

## 时间花在哪里

采用设置的分项日志中位数约为：

| 项目 | 时间 | 含义 |
| --- | ---: | --- |
| 重复 TLS 握手 | 0ms | 已复用同一条验证过身份的连接；初次连接仍需要握手 |
| 发送快照请求 | 7ms | 已建会话上的控制请求 |
| 图片读取 | 441ms | 包含等待响应、网络与 TLS 读取／解密，不能全部归为打印机处理耗时 |
| 解码与其余处理 | 387ms | 总解码阶段扣除读取／绘制后的残差，包含 ROM JPEG、缩放、校验、元数据处理及调度 |
| 显示绘制 | 54ms | 包含显示锁等待与条带 SPI 提交／完成 |
| 成功后的间隔 | 100ms | 独立配置的调度／请求间隔 |

分项中位数不能严格相加成为总中位数。此次主要改善来自取消每帧握手和缩短额外等待，不需要改变屏幕颜色／方向、提高 SPI 时钟、扩大 LVGL 池或分配完整图片。

LCD 总线并不是四秒半的硬性限制：仅 240×135 RGB565 像素在 40MHz SPI 上的理想传输时间约为 `240×135×16÷40,000,000 = 12.96ms`，这不包含命令、调度、互斥和绘制开销，不能据此宣称相机能达到约 77fps。[ESP-IDF 的 LCD 文档](https://docs.espressif.com/projects/esp-idf/en/v5.5.3/esp32/api-reference/peripherals/lcd/index.html)说明了像素数据提交接口。

当前 JPEG 路径还需接收并解码原始 1080p 图片，缩小显示区域不等于服务器发送了小图片。想继续明显提速，应优先研究读取／解码耗时或打印机是否支持较小源图片；这里没有证明 CYD 的绝对硬件极限。官方 Studio 的同一预览槽也被标成非连续视频的预览图片，不应把本次结果当作 RTSPS/H.264 视频能力。[Bambu Studio 源码](https://github.com/bambulab/BambuStudio/blob/master/src/slic3r/GUI/MediaPlayCtrl.cpp)

## 实现与配置

- CYD 默认 `CONFIG_CAMERA_REUSE_SESSION=y`、`CONFIG_CAMERA_REFRESH_DELAY_MS=100`。
- Passport 默认仍为每张重连和 2000ms 间隔。本轮没有对 Passport 做性能实测，不直接替它开启长连接。
- 只复用 JPEG 文件预览通道；未实测的 A1/P1 JPEG 流通道保留原来的连接／跳过缓存帧路径。
- 成功图片仍检查长度、偏移及 MD5。初次连接仍验证证书序列号与指纹；持久化失败不能继续认证；复用会话读写时也检查身份校验失败标记。
- 失败或 WiFi 断开时关闭 TLS；离页、息屏或换机时关闭原连接，新页面／机器重新建连。失败保留独立 5 秒退避，按键手动刷新仍可跳过成功后的间隔。
- 保持动态 JPEG 尺寸适配与分块解码，不扩大 LVGL 池，不缓存整张 JPEG／RGB。原有供电、亮屏、休眠状态机没有改动。

`camera: perf` 日志输出分项耗时、字节数、读写次数及内容是否变化；`camera: frame` 输出总耗时、结束后堆和任务栈余量。原始日志、证书、照片、设备配置和各轮固件保留在本地忽略目录，报告只记录聚合结果。

性能复测可在已激活 ESP-IDF 的环境中覆盖配置，保持同一目标、页面和网络，比较足够多的稳态成功图片：

```sh
idf.py -B build-cyd -D SDKCONFIG=sdkconfig.cyd -D SDKCONFIG_DEFAULTS=sdkconfig.defaults.cyd -D IDF_TARGET=esp32 -D CAMERA_BENCH_DELAY_MS=2000 -D CAMERA_BENCH_REUSE=0 build
idf.py -B build-cyd -D SDKCONFIG=sdkconfig.cyd -D SDKCONFIG_DEFAULTS=sdkconfig.defaults.cyd -D IDF_TARGET=esp32 -D CAMERA_BENCH_DELAY_MS=0 -D CAMERA_BENCH_REUSE=1 build
# 清空覆盖值，恢复 Kconfig 配置：
idf.py -B build-cyd -D SDKCONFIG=sdkconfig.cyd -D SDKCONFIG_DEFAULTS=sdkconfig.defaults.cyd -D IDF_TARGET=esp32 -D CAMERA_BENCH_DELAY_MS= -D CAMERA_BENCH_REUSE= build
```

所有刷写仅更新应用分区，均先备份配置并回读确认刷写前后 NVS 一致；用户测试切页产生的正常页面记忆写入不与跨轮完整 NVS 字节相等混淆。正式设置关闭强制跳页／启动自测，按原有页面记忆进入监控页。

## 最终验证

50 项主机测试通过，包含实际传输函数的会话复用、请求／解码／初始化失败后重连、流协议保留原行为、离线／停止时资源释放，以及复用 TLS 读写时拒绝身份校验失败。协议、页面恢复、供电与息屏等既有回归同时通过。

CYD ESP32 与 Passport ESP32-C3 均通过 ESP-IDF 构建。Passport 的生成配置确认仍为 2000ms 且未开启连接复用，本轮未刷写 Passport。正式 CYD 固件清空性能覆盖参数后重新构建、写入和校验，原 NVS 回读一致；追加 12 张检查的间隔中位数 1.006 秒、范围 0.980–1.028 秒，成功后无取图失败。该追加检查保留正常启动和页面记忆，不包含强制进入监控页的诊断逻辑。
